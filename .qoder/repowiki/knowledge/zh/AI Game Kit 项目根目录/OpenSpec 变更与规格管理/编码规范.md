- 每个变更目录必须包含 .openspec.yaml（schema: spec-driven，至少记录 created 和 goal）、proposal.md、design.md、tasks.md 四个核心文件。
- 行为规格使用 Requirement 标题加 #### Scenario 子节的 BDD 风格（WHEN/THEN）描述可验证的行为契约。
- 已完成变更按 `YYYY-MM-DD-<slug>` 格式重命名为 `changes/archive/` 下的子目录，并保留原始 .openspec.yaml 元数据。
- tasks.md 末尾必须追加 ADR 检查条目，明确本次工作是否产生新架构决策及对应 ADR 编号。
- skip_specs: true 用于仅做设计规划不产出 delta specs 的变更（如 create-game-framework-v1）。
