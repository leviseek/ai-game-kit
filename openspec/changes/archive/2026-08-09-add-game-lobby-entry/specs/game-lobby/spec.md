## Purpose

为游戏提供统一的游戏类型列表页主入口与品类会话编排：玩家从列表选择可玩品类进入真实对战页面，退出后回到列表；不可玩品类显示占位。大厅编排与品类夹具生命周期解耦，可独立测试。

## ADDED Requirements

### Requirement: 品类展示元数据表

游戏大厅 SHALL 提供品类展示元数据（catalog）：每个游戏类型登记 id、标题、可玩标记与入口描述（route、UI 包名、组件资源名）。元数据为显式清单，MUST NOT 自动扫描品类目录；每个条目的 id MUST 与品类夹具注册表（game fixture registry）中的 id 对齐。

#### Scenario: 可玩品类登记真实入口

- **WHEN** 查询品类 card 的元数据
- **THEN** 其可玩标记为 true，且入口描述（route/包名/资源名）指向真实可打开的对战页面

#### Scenario: 不可玩品类标记占位

- **WHEN** 查询其余四类游戏类型（fight/idle/rpg/tycoon）的元数据
- **THEN** 其可玩标记为 false，列表呈现为占位而非真实入口

#### Scenario: 元数据 id 与夹具注册表对齐

- **WHEN** 校验 catalog 每条 id 与 game fixture registry 的 id 清单
- **THEN** 两者一致，不存在 catalog 有而 registry 无的品类 id

### Requirement: 品类会话进入与退出

游戏大厅 SHALL 提供品类会话（session）的进入与退出：进入时按元数据打开真实入口页并使品类夹具进入运行；退出时关闭入口页、释放会话持有的资源并停用夹具。同一时刻 MUST 至多存在一个活动会话，已有活动会话时再次进入 MUST 被拒绝。

#### Scenario: 进入可玩品类打开真实页面

- **WHEN** 玩家从列表选择可玩品类 card
- **THEN** 品类夹具被创建并启动，其入口页（route/包名/资源名对应的页面）被打开，页面呈现真实对战内容

#### Scenario: 退出品类回到列表

- **WHEN** 玩家从品类页面返回列表
- **THEN** 入口页被关闭、会话持有的资源被释放、品类夹具被停用，列表页重新可见

#### Scenario: 已有活动会话时拒绝重入

- **WHEN** 玩家已进入某品类且尚未退出，再次请求进入另一品类
- **THEN** 请求被拒绝，当前活动会话不受影响

### Requirement: 会话级资源作用域

品类会话进入时 SHALL 为品类资源（UI 包等）建立独立的资源作用域，退出时全量释放该作用域；列表页自身资源 MUST 由独立于品类会话的作用域持有，MUST NOT 在退出品类时被一并释放。品类包退出后 MUST 可被卸载。

#### Scenario: 退出释放品类包且保留列表包

- **WHEN** 玩家进入品类后退出
- **THEN** 品类 UI 包失去作用域持有、可被卸载，列表页 UI 包仍被持有、列表页保持可读

### Requirement: 页面关闭联动会话退出

玩家在品类页关闭页面返回列表 SHALL 触发会话退出清理（资源释放与夹具停用），MUST NOT 遗留运行中的夹具（时钟/输入/订阅泄漏）。重复触发退出 MUST 幂等。

#### Scenario: 导航返回触发会话清理

- **WHEN** 玩家经导航关闭品类入口页（如返回键）
- **THEN** 会话退出清理被触发，品类夹具被停用且不遗留订阅

#### Scenario: 重复退出幂等

- **WHEN** 会话已退出后再触发退出
- **THEN** 第二次退出无副作用，状态保持一致

### Requirement: 默认入口打开列表页

无启动参数时游戏启动 SHALL 打开游戏列表页作为默认主入口，MUST NOT 停留在空白状态。UI 根宿主未就绪时 MUST 具备就绪后重试打开能力，MUST NOT 依赖固定时长硬等待。

#### Scenario: 无参数启动打开列表页

- **WHEN** 不带任何启动参数启动游戏
- **THEN** 游戏列表页被打开并可见

#### Scenario: UI 根未就绪时重试

- **WHEN** 启动初期 UI 根宿主尚未就绪，请求打开列表页
- **THEN** 请求在根宿主就绪后被重试并成功打开，而非静默失败或固定延时等待

### Requirement: 列表页交互

FGUI 列表页 SHALL 渲染所有已登记游戏类型：可玩品类可点击进入，不可玩品类显示占位且不可进入。列表项点击 SHALL 触发对应品类的进入请求。

#### Scenario: 点击可玩品类进入

- **WHEN** 玩家点击可玩品类 card 的列表项
- **THEN** 触发品类 card 的进入请求，按元数据打开其入口页

#### Scenario: 不可玩品类不可进入

- **WHEN** 玩家点击不可玩品类（fight/idle/rpg/tycoon）的列表项
- **THEN** 不发起进入请求，列表项呈现占位/禁用状态
