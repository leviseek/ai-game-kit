## Context

Framework 已具备 Application 生命周期、类型化错误体系（`FrameworkError`、`isRecoverableError`）、同步幂等 `DisposeHandle`、作用域事件通道与三种时钟。当前 `assets/framework/core` 下没有状态机或对象池。根入口 `index.ts` 以 26 项白名单导出稳定契约与必要工厂，`public-boundary.test.ts` 用 `expectedRootExports` 断言锁定。

本设计对应 `proposal.md` 和 `specs/{fsm,object-pool}/spec.md`，承接父级 change `create-game-framework-v1` 的任务 3.5–3.8。

## Goals / Non-Goals

**Goals:**

- 以声明式转移表表达状态机规则，保证转移合法性、钩子顺序与失败后状态一致性。
- 提供显式所有者对象池，覆盖容量上限、重复归还拒绝、reset 与释放，避免高频分配。
- 保持纯 TypeScript、不依赖 Cocos，可被 Bun 测试确定性覆盖。
- 沿用根入口白名单，仅导出稳定契约与必要工厂。

**Non-Goals:**

- 不引入业务语义或框架内业务状态机模板（场景、UI、玩法各有各的状态）。
- 不自动池化任意 Cocos Node，不接管 Cocos 对象生命周期或组件复用。
- 不实现通用 Scope、引用计数或资源生命周期；对象池只管理它显式持有的对象。
- 不实现分层/嵌套状态机、历史状态、并行区域等 UML 高级语义。
- 不把状态机或对象池挂到 `ApplicationContext` 或全局单例上。

## Decisions

### 1. 状态机使用声明式配置 + 轻量运行器

状态机由一个转移表（状态 → 事件 → 目标状态）和一个轻量运行器组成。运行器持有当前状态、转移表、进入/退出钩子注册表；事件发送时校验当前状态是否允许该事件，拒绝非法事件并保持状态不变。

**理由：** 声明式配置让 SceneFlow 等调用方以数据表达规则，运行器逻辑小、易测试；与父级"无业务含义的纯工具"目标一致。

**未采用方案：** 不引入状态图（statechart）库或运行时反射，避免新依赖与魔法语义。

### 2. 钩子失败采用"退出后回滚 + 错误报告"策略

转移执行顺序为：校验合法 → 运行原状态退出钩子 → 切换状态 → 运行目标进入钩子 → 转移完成。若任一钩子抛错：不执行后续钩子，状态回滚到原状态（进入钩子失败时回滚），失败经错误报告回调隔离（对齐调度器 `onTaskError` 与事件通道错误报告模式），机器保持可继续使用的一致状态。

**理由：** 保证"失败后状态一致性"可测试、可断言；错误不吞掉，通过既有诊断边界观察。

**未采用方案：** 不让状态机自动捕获并吞掉钩子错误；不采用"先切状态再运行钩子且失败不回滚"的简化实现，那会留下无法恢复的中间状态。

### 3. 状态机复用同步幂等 `DisposeHandle`

`reset()` 回到初始状态并保留配置；`dispose()` 返回同步幂等 `DisposeHandle`，释放后拒绝后续事件且不触发钩子。重复释放无副作用。

**理由：** 延续 Foundation 已验证的最小句柄模式，与调度器、事件通道一致；避免本 Change 定义新生命周期原语。

### 4. 对象池使用显式所有者 + 空闲列表

对象池持有唯一所有者，以空闲对象列表管理复用。借出时从空闲列表弹出（不足时按工厂创建），归还时执行 reset 后放回空闲列表。重复归还通过对象身份集合拒绝，避免同一实例同时借给两个调用方。容量上限约束池受管对象总数（空闲 + 借出）；池满（受管对象全部借出）时继续借出由工厂按策略创建临时对象并标记为可观察结果，临时对象归还后直接丢弃、不进入空闲列表。

**理由：** 显式所有者避免全局单例池与隐式生命周期接管；对象身份集合以 O(1) 判定重复归还。

**未采用方案：** 不自动池化 Cocos Node/Component，不建立可增长至任意上限的内存缓存，不做弱引用回收（显式所有权下无需 GC 依赖）。

### 5. 对象池 reset 失败隔离

reset 钩子失败时该对象不进入空闲列表（按规则处置，避免把脏对象再次借出），失败经错误报告回调报告，池内其他对象不受影响。

**理由：** 与状态机钩子失败、事件处理器失败同一套"隔离 + 诊断"模式，保证池计数与可用对象一致。

### 6. 公开入口保持最小导出面

在 `index.ts` 增补状态机与对象池的稳定契约与工厂，并同步 `expectedRootExports` 白名单断言；内部运行器、空闲列表与错误细节不导出。

**理由：** 延续根入口白名单收口，保证后续模块从根入口导入而非深层路径。

### 7. 实现取舍：dispose 立即生效与钩子内重入防护

`dispose()` 在调用时立即生效（释放后拒绝事件、不触发钩子），返回的 `DisposeHandle` 仅为统一句柄形态与幂等确认，不携带"延迟撤销"语义（与调度器/事件通道句柄不同）。`send()` 在执行转移期间禁止重入：钩子内再次调用 `send` 会被拒绝并经 `onTransitionError` 报告，避免嵌套转移破坏"失败后状态一致"承诺。

**理由：** dispose 返回句柄延续 design D3 字面要求，调用方仍可统一以 `DisposeHandle` 形态持有释放确认；重入防护以一行级标志成本，保证调用方误用时机器仍保持可观察的一致状态。

**未采用方案：** 不把 `dispose()` 改为 `void`（偏离 design D3，且根入口契约按返回句柄设计）；不静默忽略重入（会留下不可观察的中间状态）。

## Risks / Trade-offs

- **[状态机钩子抛错时回滚可能掩盖部分执行副作用]** → 明确"进入钩子失败则回滚且不再执行后续钩子"，并用测试锁定顺序与回滚语义；副作用由调用方在钩子内自行隔离。
- **[对象池容量语义选择可能不完全符合未来场景]** → 本 Change 锁定"受管对象总数受容量约束 + 借出超限可创建临时对象并显式报告"的可观察语义；未来有数据驱动需求时再独立 Change 调整。
- **[重复归还判定需维护对象身份集合]** → 采用借出/归还对象集合，借出时入集合、归还时移除；测试覆盖重复归还、双重借出边界。
- **[释放后仍可能被误调用]** → 释放后拒绝借出/归还与状态机一致，测试覆盖 dispose 后调用无副作用。
- **[性能热点未证实]** → 只在本 Change 保证正确的结构与可测试性；池化/缓存优化按父级 9.5 在组合验证有数据后再做。

## Migration Plan

1. 先新增失败测试与纯 TypeScript 契约，确认现有 Foundation 测试仍可运行。
2. 实现 `core/fsm` 状态机（声明式配置、钩子、回滚、reset/dispose），再实现 `core/pooling` 对象池（空闲列表、身份集合、容量、reset、dispose）。
3. 在 `index.ts` 增补稳定导出并同步 `expectedRootExports` 白名单断言。
4. 通过 `bun run test:foundation`、`bun run test:foundation:types`、依赖边界检查与 `git diff --check` 验证，不改动 `ApplicationContext`、AppRoot 或 `startup.scene`。
5. 归档本 Change 前，将父级 `create-game-framework-v1/tasks.md` 的 3.5–3.8 与实际证据同步；如引入新的长期架构决策，先按项目规则创建 ADR。

回滚时移除新增 FSM/Pooling 代码、导出与测试，保留已归档 Foundation、Platform、Diagnostics、Events 代码；不需要迁移现有业务数据。
