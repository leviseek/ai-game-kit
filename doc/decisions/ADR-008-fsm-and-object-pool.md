# ADR-008 Finite State Machine and Explicit-Owner Object Pool

## 状态

Accepted


## 背景

父级 `create-game-framework-v1` 第 5/8 章需要两组无业务含义的纯逻辑工具：SceneFlow 的预加载/成功/失败保留/重试本质是状态机，回合制卡牌与横板格斗组合验证会复用状态机与对象池。Framework 的 `core` 下此前没有状态机或对象池；根入口以白名单方式导出稳定契约与工厂。

本 ADR 记录 change `implement-fsm-and-object-pool-v1` 产生的三个长期架构决策：声明式状态机与钩子失败回滚策略、显式所有者对象池及其容量语义、对象池 reset 失败与溢出事件的可观察报告。


## 决策

### 1. 状态机：声明式转移表 + 轻量运行器，钩子失败回滚保证状态一致

`core/fsm/StateMachine.ts` 由转移表（状态 → 事件 → 目标状态）和轻量运行器组成，`send` 校验当前状态是否允许该事件，拒绝非法事件并保持状态不变。转移执行顺序为：校验合法 → 运行原状态退出钩子 → 切换状态 → 运行目标状态进入钩子；任一钩子抛错则不再执行后续钩子，状态回滚到原状态（进入钩子失败时回滚），失败经 `onTransitionError` 回调隔离，机器保持可继续使用的一致状态。

`dispose()` 立即生效（释放后拒绝事件、不触发钩子），返回同步幂等 `DisposeHandle`；`send` 在转移执行期间禁止重入，钩子内再次 `send` 被拒绝并经回调报告。`reset()` 回到初始状态并保留配置。

**理由：** 声明式配置让 SceneFlow 等调用方以数据表达规则；错误不吞掉、经既有诊断边界观察；"退出后回滚"避免留下不可恢复的中间状态。

### 2. 对象池：显式所有者 + 容量约束"受管对象总数"，临时对象用完即弃

`core/pooling/ObjectPool.ts` 持有唯一所有者，以空闲列表 + 借出身份集合管理复用。借出时从空闲列表弹出（不足时按工厂创建）；归还时执行 reset 后放回空闲列表；重复归还经对象身份集合拒绝，避免同一实例同时借给两个调用方。

容量上限约束**池受管对象总数（空闲 + 借出）**，而非空闲列表长度：池满（受管对象全部借出）时继续借出由工厂创建**临时对象**，并经 `onPoolError` 报告溢出（可观察）；临时对象归还后直接丢弃、不进入空闲列表，因此不存在"空闲对象超过上限"的状态。

**理由：** 该语义保证"借出对象直到容量上限不超出上限"，同时"池满继续借出"仍可返回可用对象且溢出结果可观察；显式所有权避免全局单例池与隐式生命周期接管。

### 3. 对象池 reset 失败与溢出经错误报告回调隔离

reset 钩子抛错时该对象不进入空闲列表（计数回退），失败经 `onPoolError` 报告，池内其他对象不受影响；工厂创建失败同样经 `onPoolError` 报告后重新抛出。错误报告器自身抛错被捕获，不影响池后续使用。

**理由：** 与状态机钩子失败、事件处理器失败同一套"隔离 + 诊断"模式，保证池计数与可用对象一致。

### 附注：根入口平铺导出

FSM 与对象池的稳定契约与工厂（`StateMachine`/`StateMachineOptions`/`StateMachineHooks`/`StateTransitionTable`/`StateHook`/`createStateMachine`、`ObjectPool`/`ObjectPoolOptions`/`createObjectPool`）平铺加入根入口，`expectedRootExports` 白名单同步为 35 项；内部运行器、空闲列表与错误细节不导出。


## 理由

- 状态机"钩子失败回滚 + 错误回调隔离"与对象池"失败对象不入池 + 计数回退"复用同一套已验证的隔离模式，失败后结构始终一致、可测试、可断言。
- 容量语义选择"受管对象总数"而非"空闲列表上限"：两者在正常借还下观察结果相同，但前者让"借出直到上限、超限可观察"成为可断言契约，且临时对象用完即弃避免空闲列表越过上限的歧义状态。
- 显式所有权 + 身份集合以 O(1) 判定重复归还；不自动池化 Cocos Node/Component、不做弱引用回收与引用计数，避免 GC 依赖与隐式生命周期接管。
- 白名单收口保证后续模块从根入口导入，不出现深层路径依赖。


## 影响

- SceneFlow（5.6–5.7）可直接复用 FSM 表达预加载/成功/失败保留/重试；格斗/卡牌组合验证（8.2/8.5）可复用对象池与模拟时钟。
- 后续如需"预填充 N 个对象""按类型分组多池""对象复用的 GC 回收"等能力，作为独立 change 引入并明确选项，不改变本 ADR 既定默认行为。
- 对象池只管理显式持有者借出/归还的对象，不自动接管任意对象生命周期；Cocos Node 复用由场景层显式决策。
- FSM 不提供分层/嵌套状态机、历史状态、并行区域等 UML 高级语义；需要时作为独立 change 扩展。
- 根入口新增稳定符号一律同步 `expectedRootExports`；移除公开符号属破坏性变更，需独立 change。
