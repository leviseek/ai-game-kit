# ADR-006 Repeating Task Scheduling Semantics


## 状态

Accepted


## 背景

`PassiveScheduler` 支持重复任务（`schedule(cb, interval, { repeat: true })`）。当两次 `tick()` 之间时钟一次推进超过一个 interval 时，存在两种可能的语义：

- 丢弃已错过的周期，只执行一次，并从当前实际时刻重新对齐下一次到期时间；
- 追赶错过的周期，在后续每次 tick 中连续执行直到追上原相位。

design.md Decision 3 只声明"重复任务计算下一次到期时间"，未定义该语义；spec 也未明确。若不记录，未来重构可能无感改变行为，影响周期性业务（如收益结算、状态刷新）。


## 决策

重复任务采用"丢弃 missed、不追赶"语义：

- 任务在到期时执行一次；
- 下一次到期时间 = 当前实际执行时刻 + interval；
- 一次推进跨过多个 interval 时，只执行一次，不补齐遗漏周期。

该行为已由 `scheduler-reentrancy.test.ts` 的两个测试锁定：

- 一次 advance 跨多 interval 只执行一次；
- tick 抖动后相位按当前时刻重新对齐。


## 理由

- 确定性优先：追赶会引入"每个 tick 连续触发"的突发负载，放大一次大推进的影响。
- 与挂机收益"按实际到达次数结算"的常见预期一致：离线期间不产生补偿执行，结算规则由业务层决定。
- 实现简单，无复杂相位追踪状态。


## 影响

- 需要"相位对齐"或"追赶"语义的业务必须自行基于 `now()` 计算，不能依赖调度器补齐。
- `now + interval` 是锚定实际执行时刻的漂移式重排，与 `setInterval` 类似但方向由被动 tick 决定。
- 未来如需追赶语义，应在独立 Change 中新增明确选项，不改变默认行为。
